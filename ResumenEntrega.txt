--------------------------------------------------------------------------------

2.1 Front-End

  - Almacenamiento:     Supabase Storage (bucket "product-images")

  - API:                PostgREST automática sobre las tablas públicas

2.3 Despliegue y control de versiones
  - Código:             Git + GitHub
  - Front:              Vercel (build automático desde rama main)
  - Back:               Supabase Cloud
  - Variables de entorno en Vercel:
      VITE_SUPABASE_URL
      VITE_SUPABASE_ANON_KEY

3. ARQUITECTURA GENERAL
--------------------------------------------------------------------------------

  [ Navegador ]
       |
       |  React (Vercel)
       v
  [ Front-End NODO ]
       |
       |  supabase-js (HTTPS)
       v
  [ Supabase ]
       ├── Auth          → usuarios, sesiones, emails de auth
       ├── Postgres      → productos, categorías, pedidos, etc.
       ├── Storage       → fotos de productos
       └── RLS           → permisos por rol (anónimo / autenticado / admin)

El front no guarda secretos del servidor: usa la anon key pública.
Las reglas de negocio sensibles se controlan con RLS en la base.

6. FUNCIONALIDADES DETALLADAS
--------------------------------------------------------------------------------

6.1 Home
  - Hero de marca “NODO”
  - Botones a catálogo y registro
  - Carrusel automático “En rotación” con productos
  - Sección “Recién llegados”

6.2 Catálogo
  - Lista todos los productos activos
  - Filtro por categorías (chips)
  - Cada producto muestra imagen, nombre, categoría y precio

6.3 Detalle de producto
  - Nombre, descripción, precio, stock
  - Galería de hasta 4 imágenes
  - Selector de cantidad
  - “Agregar al carrito”:
      * si hay sesión → agrega
      * si no hay sesión → popup para ingresar o registrarse

6.4 Autenticación
  - Registro con nombre, email y contraseña
  - Login
  - Recuperar contraseña por email
  - Definir nueva contraseña desde el link del mail
  - Mensaje de bienvenida al registrarse
  - Redirección post-login (ej. volver al checkout)

6.5 Carrito
  - Solo usable con usuario logueado
  - Cambiar cantidades / quitar ítems
  - Resumen de subtotal
  - Si no hay sesión: “Ingresar para comprar”
  - Al cerrar sesión: el carrito se vacía automáticamente

6.6 Checkout / pedidos
  - Requiere login
  - Formulario de datos del comprador (nombre, teléfono, dirección,
    ciudad, provincia, CP, notas)
  - Elección de método de envío (precio + descripción)
  - Guarda el pedido y sus ítems en la base
  - Actualiza el perfil del comprador con los datos cargados
  - Vacía el carrito al confirmar

6.7 Cuenta del comprador
  - Edición de datos personales / dirección
  - Listado de pedidos realizados (fecha, estado, total)

6.8 Panel administrador
  - Acceso restringido por flag is_admin en profiles
  - Resumen: cantidad de productos, categorías y pedidos
  - Productos:
      * crear / editar
      * nombre, descripción, categoría, precio, stock
      * subir varias fotos (máximo 4)
      * borrar fotos individuales
      * activar / ocultar producto
  - Categorías:
      * crear / editar / borrar
  - Envíos:
      * crear / editar / borrar
      * precio y rango de días estimados
      * activar / ocultar

7. BASE DE DATOS (SUPABASE / POSTGRESQL)
--------------------------------------------------------------------------------

Tablas principales (schema public), todas con RLS activado:

7.1 profiles
  - Extiende auth.users
  - Datos del comprador (nombre, teléfono, dirección, etc.)
  - Campo is_admin (boolean) para el panel

7.2 categories
  - name, slug, description, sort_order
  - Datos actuales de ejemplo: Hogar, Tecnología, Moda, Accesorios

7.3 products
  - name, slug, description
  - price_cents (precio en centavos)
  - stock, is_active
  - category_id (FK a categories)
  - Hay productos de ejemplo precargados

7.4 product_images
  - product_id, storage_path, alt_text, sort_order
  - Máximo 4 fotos por producto (validación en app + trigger en DB)
  - Archivos en bucket Storage: product-images

7.5 shipping_methods
  - name, description, price_cents
  - estimated_days_min / max
  - is_active, sort_order
  - Ejemplos: Retiro en tienda, Envío estándar, Envío express

7.6 orders
  - user_id, status (pending/paid/shipped/delivered/cancelled)
  - montos: subtotal, envío, total
  - datos de comprador y dirección de envío al momento del pedido

7.7 order_items
  - order_id, product_id, product_name
  - unit_price_cents, quantity, line_total_cents

Seguridad (RLS) — idea general:
  - Anónimo: puede leer categorías, productos activos, imágenes y envíos activos
  - Autenticado: puede gestionar su perfil, carrito/checkout y ver sus pedidos
  - Admin: puede crear/editar/borrar catálogo, imágenes y envíos


--------------------------------------------------------------------------------
8. FLUJOS PRINCIPALES
--------------------------------------------------------------------------------

A) Visitante
   Entra → mira home/catálogo/detalle → intenta comprar → popup de registro

B) Nuevo comprador
   Se registra → (email de bienvenida/confirmación) → ingresa →
   agrega productos → checkout → confirma pedido → lo ve en “Cuenta”

C) Comprador existente
   Login → compra normalmente
   Si olvidó la clave → “Olvidé mi contraseña” → mail → nueva clave

D) Administrador
   Login con usuario admin → menú Admin →
   carga/edita productos, categorías y envíos
